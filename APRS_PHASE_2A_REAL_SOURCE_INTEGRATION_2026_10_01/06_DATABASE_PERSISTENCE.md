## 1. Executive Summary

A critical deficiency discovered during the Stage 2 audit was that `NormalizedEvidence` instances generated by `core/research_sources/` were in-memory objects discarded after execution, never written into the SQLite database.

Phase 2A implemented `ResearchSourceRegistry.persist_evidence_to_db()`, which seamlessly transforms `NormalizedEvidence` records into the canonical `intelligence_evidence` schema, respecting table constraints, foreign keys, and idempotency rules.

## 2. Table Schema Alignment

The `intelligence_evidence` table schema in `core/database.py` (lines 707-730):

```sql
CREATE TABLE IF NOT EXISTS intelligence_evidence (
    evidence_id INTEGER PRIMARY KEY AUTOINCREMENT,
    product_id TEXT NOT NULL,
    field_name TEXT NOT NULL,
    source TEXT NOT NULL,
    signal_type TEXT NOT NULL,
    conclusion TEXT NOT NULL,
    evidence_status TEXT DEFAULT 'VERIFIED',
    confidence REAL DEFAULT 0.0,
    evidence_details_json TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (product_id) REFERENCES master_products(product_id) ON DELETE CASCADE
);
```

### Schema Mapping Strategy:
- `product_id`: Extracted from target product (must exist in `master_products`).
- `field_name`: Formatted as `{source}_{signal_type.value.lower()}` (e.g., `google_trends_demand`, `gdelt_news`).
- `source`: Source name (`google_trends`, `gdelt`).
- `signal_type`: Enum string (`DEMAND`, `KEYWORD`, `NEWS`).
- `conclusion`: Human-readable summary (e.g., `Google Trends Interest Index: 55.0/100 (today 3-m, IN)`).
- `evidence_status`: Defaults to `VERIFIED` for observed live API signals.
- `confidence`: Confidence score scaled to 0-100 (e.g., 0.85 -> 85.0).
- `evidence_details_json`: Complete JSON document containing raw payload, tamper signature, payload SHA-256, and retrieval metadata.

## 3. Idempotency Implementation

To prevent duplicate row creation on consecutive research runs for the same product, `persist_evidence_to_db` implements an explicit pre-insertion uniqueness query:

```python
cursor.execute("""
    SELECT evidence_id FROM intelligence_evidence
    WHERE product_id = ? AND source = ? AND signal_type = ? AND conclusion = ?
""", (product_id, ev.source, ev.signal_type.value, conclusion))
existing = cursor.fetchone()
if existing:
    persisted_ids.append(existing[0])
    continue
```

If the exact evidence signal already exists for that product, the existing `evidence_id` is retained and no redundant row is inserted.
