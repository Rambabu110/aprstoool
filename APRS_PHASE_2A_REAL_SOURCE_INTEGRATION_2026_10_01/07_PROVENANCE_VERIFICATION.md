## 1. Executive Summary

Every evidence record generated by `google_trends` and `gdelt` adapters is passed through `EvidenceNormalizer.normalize_record()`, which invokes `ProvenanceTracker.create_provenance_record()`. This guarantees that all intelligence ingested by APRS V8 is immutable, tamper-evident, and auditable back to its exact point of origin.

## 2. Provenance Metadata Architecture

Inside `intelligence_evidence.evidence_details_json`, every row contains the following mandatory provenance fields:

```json
{
  "source": "google_trends",
  "source_type": "PUBLIC_API",
  "evidence_type": "OBSERVED_SIGNAL",
  "entity": "Smart Air Purifier",
  "raw_value": 65.0,
  "unit": "index_0_100",
  "source_url": "https://trends.google.com/trends/explore?geo=IN&q=Smart+Air+Purifier",
  "retrieval_method": "PYTRENDS_REALTIME",
  "observed_at": "2026-10-01T21:15:32.104512+00:00",
  "created_at": "2026-10-01T21:15:32.104512+00:00",
  "payload_sha256": "4b6f1...d8a2",
  "tamper_sig": "a1f9e...3c08",
  "dedup_hash": "e7c2b...9a41",
  "raw_payload": { ... }
}
```

### Forensic Properties:
1. **`payload_sha256`**: Canonical SHA-256 hash of the JSON-serialized raw response payload from Google Trends or GDELT. Any mutation of the raw response in the database causes immediate hash mismatch.
2. **`tamper_sig`**: HMAC/SHA-256 signature calculated over `[source, entity, value, observed_at, payload_sha256]`, binding the evidence statement to its timestamp and content.
3. **`dedup_hash`**: Hash of `[source, signal_type, entity]`, enabling exact dedup matching without string parsing.
4. **`retrieval_method`**: Explicit technical protocol (`PYTRENDS_REALTIME`, `GDELT_TIMELINE_VOL_V2`).
